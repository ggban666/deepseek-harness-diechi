## 2026-08-23（原方案收尾）：语音打断回灌接通 + TTS 供应商预设/伪流式 + 视觉记忆自动清洗

### 1. 语音打断链路接通（此前被流式改造误删，语音"说不出来"的根因）
- 根因：7c7c2c0 全双工流式改造时，把 CameraChatDock 的 speak 注入与「ASR 转写回灌视觉模型」整段删掉，导致持续语音对话模式下：用户说话 → 转写只进草稿 → 模型听不到用户说了什么 → 也不朗读回复；speakingRef/lastSpeakAtRef 只声明从不置位，VAD 回声抑制失效。
- 修复：CameraChatDockInjected 恢复 speak(text)（controller 注入 	his.speak）；processSegment 转写成功后：以 【用户语音】{text} 前缀回灌视觉会话（结合当前帧）→ 流式回复 → 朗读回复；speakingRef/lastSpeakAtRef 在朗读期间正确置位（抑制回声自循环）；streamTurn 增加 3s 忙等待（打断后上一轮 fetch 收尾竞态）。
- 实测：POST /api/v1/vision/stream（帧+【用户语音】）→ 15 个 delta、2.0s 出中文回复；interrupt 200、delete 200。

### 2. 视觉云端推理模型 max_tokens 修复（空回复根因）
- 根因：deepseek-v4-flash-vision-exp 是推理模型，max_tokens: 80/120 的预算被 reasoning 吃光，最终 content 为空（实测 60 token 全被思考消耗、返回空字符串）。
- 修复：client 三处视觉请求 max_tokens 80/120 → 256；VisionStreamRequest 服务端默认 120 → 256。实测 512 预算下正常出内容。

### 3. TTS 供应商预设 + 伪流式
- oice.ts 新增 VOICE_PRESETS：本机 Kokoro / MiniMax（minimax-speech-01）/ 硅基流动（Fish Speech 1.5）/ Fish Audio / OpenAI（gpt-4o-mini-tts），一键填充 endpoint/model/voice。
- VoiceSection.tsx 语音设置新增「供应商预设」下拉。
- OpenAI 兼容 provider 改伪流式：splitSpeechSentences 按句切分，逐句请求 /v1/audio/speech 边收边播（首句先出）。
- 实测：8080 /api/v1/tts/stream 2 句分块 0.7s 正常。

### 4. 视觉记忆自动清洗调度
- skill-store host 新增 ctx.effect 周期任务：启动即清一次 + 每 10 分钟对全局大脑与所有人格大脑执行 cleanupScenes(2000)（相邻同内容合并 + 超上限淘汰），随插件生命周期自动停止。
- person-brain / rag-ingest 测试全过（6+5）。

## 🔧 视觉+语音服务（D:\vision-server.py，端口 8080）

```powershell
# 手动启动（启动器会自动拉起，无需手动）
& D:\vllm-env\Scripts\python.exe D:\vision-server.py 8080
# 健康检查
Invoke-RestMethod http://127.0.0.1:8080/health
```

- `GET /health`：模型加载状态与显存
- `POST /v1/chat/completions`：OpenAI 兼容，图片识别（`image_url` data URL），前端「识别图片」走这里
- `POST /api/v1/video/describe`：multipart 上传原视频 → 服务端解码 → 模型原生视频理解 → 技能草稿 JSON
- `POST /api/v1/tts`：Kokoro 中文 TTS（`{text, voice, speed}` → wav），音色 zf_001/zf_018/zm_010/zm_016

环境：Python venv 在 `D:\vllm-env`（纯 ASCII 路径，tvm-ffi 的 C++ 在中文路径下必崩，勿移回中文目录）；transformers 5.15.0 打了 `vit_merger` 变长帧补丁；模型在 `models\MiniCPM-V-4.6`（官方权重）+ `models\kokoro-zh`（ONNX 324MB + 4 音色）。

## 2026-08-22（深夜·二）：平权技能结构升级——对话自动检索 RAG + 自动归纳闭环（阶段1核心）

### 背景（用户拍板的方案）
- 平权技能 = 数据库（记忆）+ 技能（能力）+ 身份（提示词）三者一体的「一个人」；勾选即换人（结构级热重载）。
- 模型强弱不是关键，结构做好（"残疾人穿上机甲也能健步如飞"）。
- 用户最新强调：**用户用这个人格对话的时候也要整理归纳 RAG——这是数据库存在的意义**。

### 本轮改动（全部在 host 侧，编译+测试+端到端验证通过）
1. **身份卡替代全文注入**（`skill-store.ts` `renderPersona`）：勾选技能不再把 40KB 技能全文塞进 system prompt，改为「标题/简介/适用场景 + persona.md 前 600 字符人格速览」；完整指令经技能注册按需加载（实测模型自动加载 sqe-8d skill）。
2. **对话自动检索 RAG**（新增 `<identity-memory>` 动态区块，order 11）：每次模型请求自动从每个勾选技能的大脑检索「与最近用户消息最相关」的记忆 4 条 + 知识 4 条（关键词分词打分：ASCII 词权重 2 + 中文二元组权重 1），注入为"你自己的记忆"，无需模型主动调 recall。
3. **对话自动归纳闭环**（`ctx.on('session/event')` 监听 user/message + assistant/message + turn/end completed）：每轮「用户问 + 助手答」压缩成一条情节记忆写入每个勾选技能的大脑（各截断 240 字符）；重要性分级——出现我叫/我喜欢/记住/约定/决定等信号 → 3，出现我/我们/需要/打算/计划 → 2，普通 → 1；10 分钟同内容去重由 remember 兜底。
4. **overview RPC**（`diechi-brain`）：新增 `SkillOverviewEntry/SkillOverviewSnapshot` + `@Remote('overview')`——每个技能的记忆/知识/实操条数 + 最近活动时间 + 全局待归位实操数；修复 `SkillOverviewSnapshot` 缺失导入；tsdown 重新生成 typert host/remote 产物。
5. **host 插件运行时用 lib 产物**（排查结论）：dev server 的 tsx 只负责 bin.ts，插件包走 `lib/index.js` 编译产物——**改 host 插件 src 必须 `tsc -b` + `tsdown --env.DSH_BUILD_FACE host` 才能生效**，否则"改了没反应"。
