**资源账**：显存 8G（MiniCPM 占 3.1G，剩 ~4.9G 余量）；CPU 空闲窗口大；内存可再放一个 6-13G 级模型；faster-whisper / bge 类小模型走 CPU 零显存冲突。

**三条公理（最高优先级，所有模块不得违反）**：
- A1 单调性：固化库只增不减，删除 = 标记 superseded
- A2 有界性：成本 EMA±20% 软带 + K_max 绝对硬顶（frozen_rules）
- A3 可判定性：`decide()` 查表不调 LLM；**LLM 只允许出现在 evolve 的提议器里**

## 2. 五大模块方案

### M1 视觉流式记忆（VLX-Flow 思想落地）

**调研定案**：om-ai-lab/VLX-Flow 仓库真实存在但**零代码零权重**（README + 图，"Checkpoints: Coming soon"）→ 融思想不融代码；蝶翅 VisionSession 已是七成实现。

**架构（外部框架，不碰 MiniCPM 内部）**，在 `sessions.py` 之上加三层：

1. **块摘要调度器**：每 30s 空闲窗口（复用 `recogBusy` 节流，不与主推理抢 GPU）把 captions 时间线压成一条"块记忆"（时间戳 + 一句话摘要 + 关键实体）。
2. **向量语义记忆层**：新模块 `vision/memory.py`——bge-small-zh（CPU，~100MB）+ sqlite-vec 或 numpy 余弦起步；块记忆与问答对全部入库。词频检索保留做兜底，向量分加权。
3. **检索式组装**：`_build_session_messages` 改为「top-k 语义记忆 + 最近 3 帧 + 当前帧」，token 预算恒定（≈缓存感知推理的工程等价物；线性注意力在模型内部，外部改不了，也不需要改）。

**技术选型**：bge-small-zh-v1.5（CPU）胜过引重向量库；vllm-env 需新增 sentence-transformers（一次安装）。

**验收标准**：连续"看"10 分钟后，问"刚才门口进来过什么人 / 桌上东西被动过没有"——能从语义记忆答出而非只答当前画面。

### M2 视频蒸馏 skill 线（仓颉接入，最先做）

**调研定案**：cangjie-skill 2.0（kangarooking/cangjie-skill，1.3K star，MIT）= 视频→yt-dlp 下载→ASR 文案→LLM 蒸馏→skill 的开源工作流，配套 video-downloader。**不是视频生成模型。**

**架构**：8080 新增 `POST /api/v1/video/distill` + 蒸馏模块 `vision/distill.py`：

```
上传线路：视频上传 → media.describe 全文案（视觉 captions）
        + voice.py faster-whisper 音频转写 → 双通道文案合并
        → 蒸馏 prompt 链（移植 cangjie 提取框架：信念/决策/方法/边界）
        → 产出 skill 草稿（frontmatter md，对齐 diechi-home/skills 格式）
        → 落 distill-inbox/ → 人工 review → 装入 skills/
实时线路：session captions 时间线定期批蒸馏（离线，不追求边看边生成）
```

**技术选型**：蒸馏 LLM 优先走 `vision-cloud.json` 云端通道（质量稳）；本地 Qwen3.8-1bit 作离线兜底（M4 就绪后）。不自研蒸馏提示词，直接借 MIT 的 cangjie 框架。

**为什么最先做**：改动最小（ASR 已常驻、describe 已跑通）、立刻给进化闭环造自产语料——诊断结论说根因是"没有任务流→没有失败→没有学习原料"，M2 就是原料生产线。

**验收标准**：一条 10 分钟方法类视频 → 1 个可安装、可复用的 skill。

### M3 长期记忆 × 三架构叠加（核心，骨架不动改目标）

**原则**：三架构骨架（supervisor/evolve/watchdog、mount 顺序、gateWrite）**全部不动**，只换目标函数与燃料来源。

1. **价值埋点**：把"用户返工"变一等公民——采纳 / 返工 / 重问 / 改动幅度四类信号，写 PersonBrain 时打价值标签（episodic/semantic 已有 kind，扩 value 字段）。
2. **负样本重定义**：从"watchdog 崩溃"扩为"用户返工"；崩溃仍记但降权。负样本写入点从唯一崩溃路径扩到对话路径。
3. **evolve 提议类型**：`add-rule`（禁止性）之外新增 `patch-skill`——只改 persona / 知识 / 流程（md 文件），**永不改代码**。这是打破"架构级死结"（只有一个动作=禁止）的关键。
4. **监督者升级**：golden set 回归验证（现成 CBS 雏形 C=0.75）替代"频次阈值"；frozen_rules 只管红线。
5. **唯一判据**：同类任务返工率是否随时间单调下降（C(t) 有分母了，体感样本不再为 0）。

**风险与对策**：记忆噪声误报负样本 → 双门（语义聚类 + 人工确认队列）；隐私 → 聚类/向量检索全本地跑。

### M4 Qwen3.8-27B-1bit 进化引擎（老板拍板 1bit）

**定位（重要，写死）**：试验的是**模型增强（架构放大弱模型）**，不是要强模型。1bit 不是妥协，是 S5 可证伪实验的极端测试样本——p 极低时，架构（多次采样 + 验证器 + 固化）能否把 C(N) 拉上去，这正是弱模型放大律要证的东西。

**规格查实**：Qwen3.8-27B（2026-08-14 开源，dense，原生 VLM，Apache 2.0）；unsloth UD-IQ1_S = 6.19GB，Divergence-300@32 仅 ~8%，工具调用会崩 → **不能让它做开放式生成/工具链，只做收窄任务**。

**架构与补偿设计（1bit 能用的关键）**：

1. 运行时：llama.cpp（CPU，按需加载或空闲常驻，`--grammar` / JSON schema 约束解码）→ **输出结构必然合法**，1bit 崩的是内容质量不是格式。
2. 任务收窄成选择题：聚类、检索、候选生成都由确定性代码 + bge 向量干，1bit 只做「读整理好的聚类摘要 → 从有限参数空间选并填空（改哪个 skill 的哪个字段、新内容）」——作文题变选择题。
3. 质量兜底：每条提议必须过监督者 golden set 回归 + 人工确认队列才生效；垃圾提议被拦在固化库之外，只记为实验数据。
4. 资源：6.2GB 内存，不进主对话延迟路径，3090/8080 零影响；A2 有界性约束它的调用频率。

**验收标准**：连续 7 天运行，产出 ≥10 条结构合法提议；其中被 golden set + 人工采纳 ≥1 条并生效为 patch-skill → 记录该周期内的采样成本与采纳率，作为 S5 首个数据点（p 值实测）。

### M5 端侧移植（手机 + AI 眼镜）

- **手机**：A 路线——手机只做客户端，浏览器访问 3090 Web UI（内网/Tailscale 穿透），全功能保留、工作量最小。Termux 全栈本地跑暂不做（226 包依赖审计成本高）。后期可参考 Qwen3.8-Flash 的 AndroidWorld 端侧 Agent 路线。
- **AI 眼镜**：阶段一 OpenGlass DIY（ESP32-S3，$20 BOM，CameraWebServer 固件）→ `esp32_bridge.py` 拉流 → 直接对接 `/api/v1/vision/session`——**眼镜本质只是换一个帧源**，M1 的流式记忆落地后眼镜价值翻倍（持续看+记得住）。阶段二 Rokid/RayNeo 商业适配。
- **主要挑战**：推理必须在局域网可达的 PC；无屏设备的 VAD/回声抑制；功耗与隐私合规。

## 4. 技术选型汇总

| 模块 | 候选 | 选定 | 理由 / 放弃项 |
| --- | --- | --- | --- |

| 眼镜 | 商业眼镜直连 / OpenGlass DIY | ESP32-S3 DIY → /vision/session | $20 验证帧源接入，8080 接口天然适配 |

## 附：调研原始结论（2026-08-31）

- **VLX-Flow**：om-ai-lab/VLX-Flow，2026-06-26 开源，9 commits，仅 README/图/LICENSE，checkpoint "Coming soon"。核心三要素：流式分块、双层记忆（visual cache + semantic memory）、Linear Attention 缓存感知推理。VLX 三件套 Flow/Seek/Go（项目 8-23 文档里的 vlx-seek 即此家）。
- **cangjie-skill 2.0**：kangarooking/cangjie-skill（1.3K star，MIT），视频蒸馏 = yt-dlp 下载 → ASR → Longcat/任意 LLM 蒸馏 → skill；配套 video-downloader skill。
- **Qwen3.8-27B**：2026-08-14 开源，dense 27B，原生 VLM（文/图/视频→文），Apache 2.0，qwen35 混合架构（17 全注意力 + 48 SSM 线性注意力），262K 上下文。unsloth Dynamic v3.0 量化：UD-IQ1_S 6.19GB（Div-300 ~8%，工具调用崩）/ Q2 9.8GB ~23% / Q3 13.1GB ~40% / Q4 17.6GB 63% 甜点。
